# 城市公共树木养护协作系统

用于维护城市公共树木档案、巡检任务和居民异常反馈的基础协作系统，已具备登录认证与基于角色的权限控制（RBAC）。

## 技术栈

- 前端：Vite + React + TypeScript
- 后端：Node.js + TypeScript，内置 HTTP 服务
- 数据：内存数据，方便后续替换为 Repository、SQLite 或 PostgreSQL

## 基础流程

建立树木档案 → 安排巡检 → 记录异常 → 派发养护 → 完成复核

## 角色与权限

| 能力 | 管理员 admin | 巡检人员 inspector | 居民 resident |
| --- | --- | --- | --- |
| 树木档案 | 增删改查、推进状态 | 只读 | 不可见 |
| 异常反馈 | 增删改查、推进状态 | 查看、编辑、推进养护状态 | 提交、仅查看/管理**自己发起**的反馈 |
| 巡检任务 | 增删改查、推进状态 | 新增、查看、编辑、推进状态 | 不可见 |

## 认证与权限设计

- **登录入口**：未登录访问任何业务页面都会进入统一登录页。
- **令牌会话**：`POST /api/auth/login` 校验用户名密码（scrypt + 随机盐、常量时间比较），成功后签发不透明 Bearer 令牌（服务端保存、12 小时过期）；`POST /api/auth/logout` 注销后令牌立即失效。
- **状态恢复**：令牌保存在 `localStorage`，刷新页面后通过 `GET /api/auth/me` 向服务端校验恢复；令牌无效或过期则清除并回到登录页，不仅依赖本地缓存判定登录。
- **接口保护（真正的安全边界）**：所有 `/api/trees`、`/api/reports`、`/api/inspections` 接口先认证（401 `UNAUTHORIZED`/`SESSION_EXPIRED`）再按角色权限矩阵鉴权（403 `FORBIDDEN`）。前端隐藏按钮仅用于交互体验，绕过前端直接请求接口仍会被服务端拒绝。
- **数据归属**：居民查询反馈列表/单条时服务端强制按 `ownerId` 过滤，直接拿他人记录 ID 请求同样返回 403；居民提交反馈时 `reporter`、`status`、`ownerId` 均由服务端强制写入，请求体中伪造会被忽略。
- **统一错误处理**：服务端所有错误返回 `{ error, code }`；前端统一封装 fetch，业务错误就地提示，任意请求遇到 401 自动清理会话并跳转登录页并提示原因。

## 已实现

- 登录 / 退出 / 刷新恢复登录状态
- 三类角色 RBAC：模块按角色显隐、操作按钮按权限显隐
- 业务模块切换、列表展示、新增、编辑、删除
- 基于状态的流程推进
- 居民异常反馈的归属隔离
- 未登录（401）与越权（403）统一错误结构与前端处理
- `/api/health` 健康检查（公开）
- Vite 开发代理和前后端分离结构

## 启动

```bash
npm install
npm run dev
```

前端：`http://localhost:5174`；后端：`http://localhost:4001`。

也可只启动后端（同时托管打包产物）：

```bash
npm run build
npm start
```

## 扩展点

当前业务数据与会话使用内存存储，重启后失效。后续可将会话替换为 JWT/Redis 会话、用户与数据迁入数据库、增加刷新令牌、登录失败锁定/审计、分页检索、附件上传、通知、领域事件和更细粒度的状态机校验。
