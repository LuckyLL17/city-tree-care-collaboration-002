# 城市公共树木养护协作系统

用于维护城市公共树木档案、巡检任务和居民异常反馈的基础协作系统。

## 技术栈

- 前端：Vite + React + TypeScript
- 后端：Node.js + TypeScript，内置 HTTP 服务
- 数据：当前使用内存数据，方便后续替换为 Repository、SQLite 或 PostgreSQL

## 基础流程

建立树木档案 → 安排巡检 → 记录异常 → 派发养护 → 完成复核

## 已实现

- 业务模块切换与基础列表展示
- 新增记录
- 基于状态的流程推进
- 登录认证与三类角色权限（管理员 / 巡检人员 / 居民）
- 后端令牌会话校验与接口级权限控制，统一 401 / 403 错误处理
- 前端登录入口、按角色隐藏不可用操作、刷新后恢复登录状态
- `/api/health` 健康检查
- Vite 开发代理和前后端分离结构

## 启动

```bash
npm install
npm run dev
```

前端：`http://localhost:5174`；后端：`http://localhost:4001`。

## 演示账号与角色权限

| 角色 | 账号 | 权限 |
| --- | --- | --- |
| 管理员 | `admin / admin123` | 维护全部树木档案、异常反馈、巡检记录及其状态 |
| 巡检人员 | `inspector / inspector123` | 处理巡检与养护相关记录（新建/编辑/推进状态），树木档案只读 |
| 居民 | `resident / resident123`、`resident2 / resident123` | 只能提交和查看本人发起的异常反馈 |

认证方式：登录后颁发 Bearer 令牌（内存会话，12 小时有效），前端将令牌保存在
`localStorage` 并在刷新后通过 `GET /api/auth/me` 恢复登录状态。所有业务接口均要求
携带 `Authorization: Bearer <token>`，权限矩阵在服务端强制执行（前端隐藏按钮仅为
体验优化）；未登录返回 `401 UNAUTHENTICATED`，越权返回 `403 FORBIDDEN`，错误响应
统一为 `{ "error": "...", "code": "..." }`。居民提交反馈时反馈人会被强制设为本人，
列表也仅返回本人数据，防止冒名与越权读取。

## 扩展点

当前版本使用内存存储用户、会话与业务数据。后续可增加分页检索、附件上传、通知、审计日志、数据库 Repository、领域事件和更细粒度的状态校验。
